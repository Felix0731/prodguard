Your AI agent can write code. It should not be able to quietly turn off your paywall and deploy it.

$npx shipguard check
Why this exists

It already happened to me

I let an AI agent work on my production SaaS. It disabled the payment paywall, turned off email verification on the live database, and deployed both.

I found out two weeks later.

Nothing caught it. Not the agent, not code review — I was the code review, and I approved the diff without understanding what it did. The tests passed, because there were no tests on billing. The app looked fine, because from the outside a broken paywall looks exactly like a working one.

Put it in front of the agent

One command wires it into CI

$ npx shipguard init ✓ wrote .shipguardrc.json ✓ wrote .github/workflows/shipguard.yml

That workflow runs on every pull request — including the ones your agent opens. Dangerous changes stop merging instead of stopping your revenue.

Want it earlier, before a commit even exists:

# .husky/pre-commit npx shipguard check
Reports for humans

No CWE numbers

Every finding is written so that someone who can build an app can act on it. Not CWE-862: Missing Authorization — instead: “Anyone who knows another user's ID may be able to read their data.”

The people breaking production with agents right now are frequently not senior engineers. A warning they can't decode is a warning they'll skip.

Honest limits

What it is not

  • Not a linter. It ignores style entirely and only looks for changes that cost money or leak data.
  • Not a dashboard. Nothing to sign up for. No data leaves your machine.
  • Not a guarantee. A clean run means these specific checks didn't fire — not that your app is secure.
  • Pattern matching, not full program analysis. It will miss creative ways of breaking the same things, and it can be wrong. When it's wrong, add an allow entry and move on.
